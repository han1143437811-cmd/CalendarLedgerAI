## 已修复的缺口

- 0.3.3 没有费用分摊工具，只提供普通账目新增/修改，模型需要自行拆成多笔交易，容易产生金额舍入与重复记账。
- 对话显示记录保存了，但 API 线路的 `apiHistory` 仅保存在当前页面内存；重开后没有重建旧对话和操作结果。
- 原工具循环缓存所有调用，包括查询；同轮写入后相同查询可能返回旧结果。

新实现通过 `expense-allocation.mjs`、`ai-context.mjs` 和 `ai-agent.mjs` 提供精确费用投影、每轮重建的上下文和可核对的工具执行。

## 分摊口径

用户选择“保留付款记录，日历按天分摊”。真实交易仍是原来的付款，统计、预算和 CSV 使用实际付款日期。应用月/周历与原生小组件采用按日费用；当天详情明确区分实际付款与日均费用。组件标题显示“费用按日”。

`allocate_expense` 接收真实支出 ID，可一次处理 1—50 笔。未指定期间的月订阅按源付款所在自然月分摊；明确指定 `start/end` 时采用连续服务期间，支持 1—366 天。收入、退款、转账不能作为分摊源。取消分摊使用 `remove_expense_allocation`，不会删除原付款。

所有金额以整数分计算。总价 3000 分除以 31 天，前 24 天每天 97 分、后 7 天每天 96 分，总计仍为 3000 分。0.01 元的长期间也不会生成假交易或存储零值付款。分摊计划只保存源 ID 和起止日，不复制金额，修改源付款后每天费用自动重新计算。

同一计划再次执行不添加第二份、不制造额外撤销记录。批量分摊验证整组对象后原子写入；删除源付款同时删除关联计划，撤销可以恢复两者。分摊中修改收支类型需要先取消分摊。

`query_cashflow` 查询实际收支，`query_daily_costs` 查询按天费用，两种口径明确区分。退款仍按实际登记日期抵减支出，内部转账不计收支。不是余额预测、自动扣费或订阅续费管理。

## 记忆与上下文

- 长期偏好：最多 40 条，每条名称 60 字、内容 300 字；用户明确说“记住”“以后默认”时使用 `remember_preference`，同名称更新。`forget_preference` 可以忘记单条或全部，并支持撤销。
- 近期对话：本机保留最近 200 条显示消息，重开应用后恢复。每次 API 请求从已保存数据重新构建最近最多 24 条消息，历史正文预算 40000 字符，并附必要的真实对象 ID 与最近操作结果。
- 更早内容：`search_chat_history` 按关键词检索仍保存在这 200 条消息中的内容。没有无限记忆，也没有自动总结所有人生信息。
- 当前状态：每轮带上日期、时区、当前界面、已创建对象、日历、账本、偏好和部分分摊计划。计划最多取最近 20 条及总数，避免把整个账本作为系统上下文。
- 图片：此前图片保留缩略图及识别卡片，不把完整图片重新发送给模型。需要重新识别时用户再次附图。

入口为“更多 → AI 记忆”，聊天顶部也有记忆按钮。记忆页可新增、覆盖同名偏好、忘记单条以及清空聊天上下文。清空聊天不删除偏好、账目或日程。偏好与分摊计划随业务 JSON 备份导出；旧备份没有这些字段时按空数据兼容恢复。

偏好在本机保存。使用远程 AI 时，必要偏好、近期对话和操作上下文会发送至用户配置的服务。密钥使用既有专用配置与 Keystore；记忆工具拒绝明显的 API Key/密码类偏好，不把密钥放入业务记忆。

## 工具循环

写入前递归验证 JSON 工具参数，包括必填字段、类型、枚举和未定义字段。成功写入按规范化参数去重，查询不缓存，失败调用可以修正后再次执行。同轮最多 12 轮，每个响应最多 30 个工具调用。

分摊与记忆请求若只有“已经完成”的文字、没有对应工具成功结果，会补一次执行核对；仍未执行时明确提示未完成。接口中断后保留已经成功的本地操作，并显示可撤销结果，不自动再记一遍。

## 验证边界

整数分算法、月长/闰年、跨月、重复执行、金额修改、取消/删除/撤销、旧备份和持久偏好通过自动检查。浏览器模拟 API 检查覆盖 HTTP → 工具调用 → 本地写入 → 再次统计，并验证页面重载后的上下文。Android 使用交付 APK 的真实 WebView、原生桥接和 AppWidgetHost，验证分摊金额、冷启动、跟进修改及记忆界面。

模拟 API 验证应用执行链路，不代表真实 DeepSeek 的所有自然语言表达都已测试。本次不使用真实用户 API Key，也没有操作用户 S24 Ultra。模型在对象选择、含糊日期和语言理解方面仍可能出错；实际效果需结合用户配置的服务确认。
