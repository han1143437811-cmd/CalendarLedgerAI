# v0.3.9：给 AI 提供实时设备时间

2026-10-14。旧版只在会话提示中提供日期与时区，缺少时分秒，也没有在工具后续请求中刷新。

每次聊天请求（包括工具调用后的继续请求和上下文摘要）都会在系统消息中附带当前设备时间：当地日期、24小时制时分秒、中文星期、时区名称、UTC偏移、UTC时间与毫秒时间戳。Android 直接读取本机系统时钟；浏览器预览读取客户端时钟。时间由应用提供，不依赖模型猜测、API服务器时区、网络授时或当前查看的日历月份。

同时保存用户消息的发送时间。询问“现在几点”以本次请求时间为准；“今天/明天/半小时后”等相对安排以该用户消息的发送时间为基准，避免工具执行较久或跨午夜后目标时间发生漂移。用户明确指定的日期、时间和时区优先。已有日程字段仍按分钟记录，时分秒的上下文不改变其存储格式。

历史消息保留自身的发送时间，进入后续上下文、历史检索、有限摘录和摘要时仍携带该时间。旧版没有时间戳的聊天继续兼容，助手不得根据当前日期猜测旧消息发生在哪一天。原聊天与分支继续保留时间信息。

当前时间在每次请求时重新取得，包含时区及当日实际UTC偏移，支持午夜换日和夏令时。它表示请求发送时刻；模型生成耗时较长时不能把它宣称为回答结束瞬间的精确时钟。时间依据设备系统设置，应用不校准手机时钟。无需联网、定位或新权限，也不新增后台定时任务。

## 实现与验证

- prototype/ai-time.mjs：格式化、验证设备时间并生成每次请求的时间上下文；不会改写工具与思考消息。
- Android DeviceTime / CalendarAndroid.currentTime：读取系统时钟和系统时区；页面端优先使用原生时间。
- requestAI 在调用聊天或摘要前刷新时间；用户和助手消息的发送时间保存在已有快照中。
- 自动上下文压缩保留原消息时间；当前时间消息不存入旧API工具调用记录。
- 单元检查覆盖UTC与当地跨日、负时差、非整小时时差、夏令时重复时刻、工具中途跨午夜、历史与摘要时间、原生读取及无效数据回退。
- 浏览器使用受控客户端时间，经过实际应用和本机代理检查上游请求，并验证相对时间创建的实际日程、摘要请求、重启与时区切换。
- Android 在真实WebView/HTTPS桥接上读取系统时钟，用测试网关确认第一轮与工具继续轮都收到最新时间，并检查保存与重启。测试代码与网关不包含在交付APK中。

未使用用户真实API Key，也未在用户S24 Ultra / One UI 8.5实机验证模型对时间信息的理解质量。安装包哈希与逐项结果见 dist/验证结果-v0.3.9.json。
